# 真实账号人工验收步骤（Manual Test）

> 版本：0.1.7 ｜ 更新：2026-08-15
> 前置：本仓库开发环境无法登录真实 Bilibili 账号，以下所有「接口行为」结论都需人工验收。
> 验收前先备份数据（设置页 → 数据 → 导出备份）。

## 0. 环境准备

1. Chrome/Edge 加载未压缩扩展：`out/chrome-mv3`（设置 → 扩展程序 → 开发者模式 → 加载已解压的扩展程序）。
2. 登录 Bilibili（普通账号即可，建议小号）。
3. 打开设置页，完成「自动举报授权」并选择默认理由。

> 2026 页面已使用 `<bili-comments>` open Shadow DOM。自动测试通过不等于本节通过；必须在上述真实浏览器中观察扩展按钮、排序、懒加载与 SPA 行为。

## 1. 页面适配验收（选择器）

| # | 步骤 | 预期 |
|---|---|---|
| 1.1 | 打开任意视频页评论区 | 每条一级评论右上角出现快捷按钮（悬停显示） |
| 1.2 | 展开楼中楼 | 每条楼中楼回复有快捷按钮 |
| 1.3 | 评论排序切换（热门/最新） | 按钮重新注入且不重复 |
| 1.4 | 下滑加载新评论 | 新评论自动注入 |
| 1.5 | SPA 切换到另一个视频 | 按钮正常，aid 更新（举报的 oid 正确） |
| 1.6 | 打开动态首页 | 每张动态卡片有快捷按钮 |
| 1.7 | 打开动态详情（/dynamic/{id} 与 /opus/{id}） | 卡片与评论区按钮正常 |
| 1.8 | 打开动态详情评论区 | 动态评论按钮正常 |

失败处理：选择器失效时，把页面元素拷贝到 `tests/fixtures/pages/`（脱敏）并更新 `src/adapters/bilibili/selectors.ts`。

## 2. 官方拉黑验收

| # | 步骤 | 预期 |
|---|---|---|
| 2.1 | 对任一评论点击「官方拉黑但不举报」→ 等待倒计时 | Toast 显示「官方拉黑成功」 |
| 2.2 | 到对方主页/好友页确认 | 该账号已被拉黑 |
| 2.3 | 对同一账号再次点击 | 不重复请求（去重），不报错 |
| 2.4 | 退出登录后点击 | Toast「拉黑失败：未登录」，队列暂停 |
| 2.5 | 再次触发风控场景（如频繁操作） | 队列暂停并提示「验证码/风控」，无自动化重试 |

## 3. 自动举报验收

| # | 步骤 | 预期 |
|---|---|---|
| 3.1 | 确认默认理由为「垃圾广告」(reason=1) | — |
| 3.2 | 一键拉黑并举报 → 倒计时内点「取消全部操作」 | **无名单写入、无任何请求、节点恢复显示**（P0-2 完整回滚） |
| 3.3 | 一键拉黑并举报 → 倒计时内点「仅取消官方任务」 | 本地名单已写入、节点保持折叠、无任何请求 |
| 3.4 | 一键拉黑并举报 → 倒计时进行中（结束前）检查 storage | `bb.blocked`/`bb.verified` 尚无该 UID（延迟提交） |
| 3.5 | 一键拉黑并举报 → 等待完成 | 拉黑成功 + 举报成功（Toast 分别显示）；名单在倒计时结束后才出现 |
| 3.6 | 已 blocked 未 verified 的 UID 再次一键 → 取消全部操作 | 原 blocked 记录保留（blockedAt 不变）、不新增 verified |
| 3.7 | 已 verified 的 UID 一键 → 取消全部操作 | 原 verified 记录保留 |
| 3.8 | 用「举报查询/举报记录」渠道核实 | 该评论确有举报记录，理由与设置一致 |
| 3.9 | 更换默认理由为「赌博诈骗」(12) 再举报一条 | 记录中 reason 为 12 |
| 3.10 | 手动改坏配置（把理由改成无效 id）后举报 | 停止提交并提示「举报理由已失效」 |
| 3.11 | 动态本体举报（在动态卡片上一键处理） | 记录中动态举报成功（若端点 404/报错，说明动态举报端点需更新，改 `src/adapters/bilibili/report.ts` 并同步 docs/bilibili-research.md） |

**特别注意（对应产品定义 §4/§5）**：
- 仅命中关键词/正则的“疑似”内容：**不得**出现拉黑/举报请求（应只折叠/标记）；
- 已确认机器人发布的普通内容：自动处理开启时也只拉黑不举报；
- 举报提交后无法撤回。

## 4. 自动处理已确认机器人验收

1. 设置 → 开启「对已确认机器人自动处理」+ 授权。
2. 在名单中添加一个测试 UID（或对内容点一键处理）。
3. 该 UID 发布命中广告关键词的内容出现时：内容折叠 + 倒计时提示 + 自动拉黑/举报（需同时满足账号授权证据与独立内容违规证据）。
4. 关闭开关：恢复为仅折叠，不再自动操作。

## 5. 数据与恢复验收

- 导出备份 JSON → 清空全部数据 → 导入备份 → 数据完整（含危险正则/超深条件树的导入被整体拒绝）。
- 重启浏览器后队列未完成任务继续执行（可在操作延迟较大时验证）。
- 操作日志：仅含必要字段，无正文。
- 设置页在「自动举报」卡片中看到能力验证状态（未验证能力禁用授权与自动处理开关并给出原因）。
