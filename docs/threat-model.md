# 威胁模型（Threat Model）

> 版本：0.1.0 ｜ 更新：2026-08-13

## 1. 资产

- 用户 Bilibili 账号（登录态、拉黑/举报操作的账号影响）
- 用户本地数据（规则、名单、日志）
- 用户隐私（浏览行为、评论/动态内容）

## 2. 信任边界

```
Bilibili 页面 DOM/JS ──内容脚本(隔离世界)── 扩展后台 ── chrome.storage.local
        │                                          │
        └──── 内容脚本 fetch（同源 Cookie + CORS） ─┘
```
- 内容脚本与页面主世界隔离（MV3 isolated world）；
- 页面 DOM 与页面脚本视为**不可信输入**；
- 扩展只向 Bilibili 第一方域名发请求；本地存储视为可信但按容量约束。

## 3. 攻击者模型

| 攻击者 | 目标 | 影响面 |
|---|---|---|
| 恶意 Bilibili 内容（评论/动态注入脚本） | 在扩展 UI 注入 HTML/JS | 已控制：textContent-only、Shadow DOM 隔离 |
| 恶意第三方页面 | 冒充扩展消息/请求 | 已控制：host 白名单 + 消息校验 + onMessageExternal 拒绝 |
| 恶意规则导入 | 原型污染/超大结构/代码执行 | 已控制：Zod strict + 大小限制 + 危险键剥离 + 无代码字段 |
| 恶意正则 | 页面卡死（ReDoS） | 已控制：长度/输入限制 + 启发式拒绝 + Worker 时间预算 + 出错禁用规则 |
| 网络劫持（Bilibili 接口被篡改） | 伪造成功/诱导操作 | 已控制：HTTPS + 响应 code 标准化 + 未验证不显示成功 |
| 用户误操作 | 误拉黑/误举报 | 已控制：倒计时取消、白名单、账号保护、明确披露 |

## 4. 已接受的风险

1. 举报成功无法撤回（产品披露项，非漏洞）。
2. 拉黑接口未登录/风控时的失败重试窗口内可能重复点击（去重表兜底）。
3. 页面改版导致选择器失效 → 功能降级（只隐藏）而非崩溃（多候选 + 优雅失败）。
4. 内容脚本 fetch 依赖 api.bilibili.com CORS 策略；若 Bilibili 收紧 CORS，功能将降级为「仅本地隐藏 + 手动操作」，代码路径已标准化（network/api_changed 结果），不冒充成功。

## 5. 隐私

- 无遥测、无指纹、无广告 SDK、无第三方服务器；
- 日志不存正文（仅 UID/用户名/内容 ID/时间/结果）；
- 不上传 Cookie/CSRF/黑名单/举报日志；
- 商店声明与 PRIVACY.md 与实际行为一致。
