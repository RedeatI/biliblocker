## 1. 商店材料（简体中文）

### 名称

`BiliBlocker — Bilibili 评论与动态的本地内容治理`

### 简短说明（≤132 字符）

`在本地解释、折叠并可恢复地管理 Bilibili 评论与动态中的疑似广告、营销与垃圾内容。`

### 详细说明（正文）

```
BiliBlocker 是 Bilibili 视频评论、楼中楼回复和动态的本地、可解释、可恢复治理层：它按你选择的规则标记、折叠或隐藏疑似广告、营销引流与垃圾内容，并可将你确认的账号加入本地名单。命中原因会在页面中显示，折叠内容可在页面内恢复。

主要功能：
1. 本地规则隐藏：按关键词、链接、域名、正则、用户名、UID 折叠或隐藏疑似广告内容（规则由你创建，默认本地保存）。
2. 一键拉黑并举报：官方拉黑/举报请求默认关闭。只有在人工验证相关能力、你明确授权并选择默认举报理由后，才会在倒计时结束时尝试执行；倒计时内可取消。
3. 三种名单：本地黑名单、已确认机器人名单、白名单，均可导入导出。
4. 自动处理开关：对已确认机器人名单中的精确 UID，且内容命中你设定的规则时，可在已验证能力下排队处理（默认关闭，仍有倒计时可取消）。
5. 操作日志：全部本地保存，可查看、筛选、导出（不含评论正文）。

重要披露：
- 首次安装保持总开关关闭，并先让你在「仅标记（推荐）」「折叠」或「保持关闭」之间知情选择；升级不会覆盖既有设置。
- 扩展会读取你打开的 Bilibili 页面中的评论与动态内容（仅在你打开 Bilibili 页面时，用于本地过滤）。
- 官方请求默认关闭，且拉黑、举报与页面适配能力仍须人工验证；当前未验证时不会发送 Bilibili 官方请求。
- 若你在未来启用已验证的官方请求，扩展才会代表你调用拉黑或提交举报（举报首次使用还需授权并选择默认理由）。
- 数据默认保存在本地（chrome.storage.local）。
- 举报提交成功后无法由扩展撤回。
- 扩展不收集、不出售、不共享任何用户数据；不向任何第三方服务器发送评论、动态正文或你的任何数据。
- 真实接口能力门禁：拉黑、举报、页面选择器等能力须经真实账号人工验证（docs/REAL-ACCOUNT-VALIDATION-RECORD.md）后才会启用；未验证前扩展仅提供本地规则过滤与名单管理，不会向 Bilibili 官方接口发送任何请求。
- 本扩展不是 uBlock Origin（uBO）或任何通用网络广告拦截器的替代品；不绕过付费、会员或访问限制；推荐内容、观点或账号本身不因“不喜欢”而自动等同违规。

本扩展为第三方非官方扩展，与哔哩哔哩（Bilibili）官方无关。
```

### 类别与标签

工具 / Productivity；标签：`bilibili`、`评论管理`、`动态管理`、`本地规则`、`内容过滤`

## 5. 权限用途说明（商店权限提示文案）

- `alarms`：后台队列的定时唤醒；仅在用户启用且能力已人工验证后才可能用于官方操作。
- 读取 www.bilibili.com 页面：在本地过滤内容并注入快捷按钮；官方操作默认不发生，启用后仅使用你的页面登录态。

## 8. 提交流程

1. 在干净候选工作树运行 `pnpm zip`，核对 `dist/build-info.json` 中完整 source commit、dirty/例外状态、manifest 摘要/相对基线差异、三包 SHA-256/size/entry count。
2. Chrome Web Store 开发者后台创建项目 → 上传 Chrome ZIP → 填写材料 → 提交审核。
3. 确认 `docs/REAL-ACCOUNT-VALIDATION-RECORD.md` 已完成适用的人工验证；否则仅以“本地过滤与名单管理、官方请求关闭”的能力边界提交。
4. Edge Add-ons 后台（Partner Center）创建提交 → 上传 Edge ZIP → 填写材料 → 提交。
5. 提交前核对最新官方政策（链接见本文档头部）。
6. **未实际完成商店提交与审核前，不得声称“已经发布”。**
7. 截图和主宣传图仍是外部人工交付门槛；缺失时不得提交，也不得伪造完成状态。
